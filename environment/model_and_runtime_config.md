# Model and Runtime Configuration

This file lists the shared setup and the approach-specific settings used for all experiments (RQ1–RQ3). The paper's **fairness controls** require every approach to use the same model, workbooks, scenario partition, oracle, matching predicate, Java environment and budget.

---

## 1. Shared setup (all approaches)

| Item                 | Setting                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LLM                  | GPT-5.6, deployment `gpt-5.6-sol` (the same deployment for A1, A2 and Ours)                                                                             |
| API                  | Azure OpenAI Chat Completions API                                                                                                                       |
| Credentials          | Environment variables (`AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_DEPLOYMENT`); not included                                        |
| Target language      | Java 20, compiled with `javac`, using only the standard library                                                                                         |
| Platform             | Windows (Microsoft Excel required for the oracle)                                                                                                       |
| Test oracle          | Microsoft Excel recalculation: scenario inputs are applied to the workbook and Excel recalculates every formula                                         |
| Pass criterion       | The program compiles and runs, and **every** formula cell matches Excel under the type-aware predicate ≈                                                |
| Matching predicate ≈ | Numbers and dates within configurable tolerances; strings, Booleans and Excel error codes exactly; blanks and arrays use Excel-compatible normalization |
| Scenario partition   | Random split, done once per workbook: $T_{in}$ ≈ 20% (45 scenarios) and $T_{out}$ ≈ 80% (176 scenarios); shared by all approaches                       |
| Held-out protocol    | Once $T_{in}$ passes, the program is frozen and run once on $T_{out}$; no further repair                                                                |
| Hard-coding rule     | Every approach is told not to hard-code scenario inputs or expected outputs                                                                             |
| Runs                 | One run per approach and workbook; LLM outputs are non-deterministic                                                                                    |

## 2. Approach-specific settings

### Ours: Structured validation-driven synthesis

| Item                   | Setting                                                                                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Prompts                | [`prompts/Ours/Prompt_Templates.md`](../prompts/Ours/Prompt_Templates.md) (T1–T4)                                                               |
| Value model            | `XlType` / JavaXl records with Excel semantics (including the 1900 leap-year date serial)                                                       |
| Excel function library | `ExcelUtils`, generated by T1 and checked against Excel-calculated examples                                                                     |
| Repair budget          | Up to 7 repair rounds per Excel function (T1) and per code block (T3/T4)                                                                        |
| Prompt limits          | At most 2 examples per function (T1); at most 15 errors per repair prompt (T4)                                                                  |
| Repair scope           | Localized: the mismatch frontier and sub-formula localization, with cumulative regression checks over every previously passing in-loop scenario |
| Recorded metrics       | `logs/summary.txt`: tokens, repairs, stage times (preprocessing, seed synthesis, validation)                                                    |

### A1: Global agentic repair

| Item             | Setting                                                                                                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prompts          | [`prompts/A1/`](../prompts/A1/README.md): P1 system, P2 initial generation, P3 compile repair, P4 unmatched repair, P5 counterexample repair                                 |
| Output           | One self-contained Java program (`WorkbookProgram`), run once per scenario with runtime input overrides                                                                      |
| Repair scope     | Whole program: regenerated from compiler errors (P3), from cell mismatches when no scenario passes (P4), or from up to 3 passing and 3 failing scenarios when some pass (P5) |
| Repair budget    | Until all in-loop scenarios pass or the repair budget is exhausted; the attempts used are recorded in `final_logs.json` (`repair_attempts`, 0–3 across workbooks)            |
| Recorded metrics | `final_logs.json`: `total_tokens`, `time_in_sec`, `repair_attempts`, pass counts                                                                                             |

### A2: Role-specialized agentic workflow

| Item                          | Setting                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Prompts                       | [`prompts/A2/Prompt_Templates.md`](../prompts/A2/Prompt_Templates.md) (S1–S6 synthesis, R0–R4 repair)                   |

| Recorded metrics              | `summary.json`: pass counts, cells, `elapsed_time_seconds`                                                              |

## 3. Ablation runs (RQ3)

The ablation variants use the **Ours** configuration above, with exactly one component disabled in each:

| Variant folder                   | Component removed                                         |
| -------------------------------- | --------------------------------------------------------- |
| `without_fault_localization`     | Mismatch-frontier / sub-formula fault localization        |
| `without_multi_scenario_repairs` | Cumulative multi-scenario regression checks during repair |
| `without_xltype`                 | `XlType` Excel-compatible value model and runtime         |
| `without_loop_inference`         | Loop inference in the loop-aware IR                       |

All other settings (model, prompts, budgets, oracle) are the same as in the full pipeline. See [`results/rq3_ablation_study/`](../results/rq3_ablation_study/README.md).
